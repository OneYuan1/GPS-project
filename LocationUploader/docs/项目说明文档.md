# LocationUploader 项目说明文档

## 第 1 章 研发目的

### 1.1 项目背景  
智能手机集成了完整的 GNSS（Global Navigation Satellite System）接收机、定位算法与网络能力，可在成本极低的情况下完成高频率定位与数据上传。相比传统“独立 GPS 模块 + 上位机软件”方案，使用手机作为采集终端具有部署简单、便携、可视化能力强等优势，非常适合教学演示、科研试验与快速验证。

### 1.2 核心功能  
- 通过 Android 系统的 `LocationManager.GPS_PROVIDER` 获取真实的卫星定位数据；  
- 实时显示经纬度、高度、速度、航向、精度和卫星状态；  
- 将 `Location` + GNSS 状态数据打包为与 `gnss_data.h` 对齐的二进制数据包；  
- 采用 **TCP** 上传方式，将数据发送至云服务器上的 Java 接收服务并存入 MySQL；  
- 支持本地/远程网络配置、TCP 连通性测试以及上传状态反馈。

### 1.3 研发目的（修正）  
1. **教育演示**：完整展示“终端获取 → 数据打包 → 网络传输 → 云端落库”的 GNSS 数据链路，并向学生/爱好者可视化呈现多维定位信息。  
2. **数据采集**：为轨迹记录、位置服务、科研分析提供稳定可靠的 GNSS 原始数据来源，可连续采集并上传。  
3. **技术验证**：验证从 Android 终端、二进制协议、TCP 传输到云端 MySQL 的可行性，为后续扩展（可视化、异常检测、GNSS 欺骗检测等）奠定基础。  
4. **低成本部署**：仅依赖一部 Android 手机和一台云服务器，免去额外硬件采购与复杂布线。

### 1.4 预期成果  
- 可稳定运行的 Android APP——`LocationUploader`；  
- 一套配套的云端接收/存储工具（Java 接收程序 + MySQL 数据库脚本）；  
- 完整的文档体系（部署说明、版本说明、项目总结、该说明文档等）。

## 第 2 章 研发过程

### 2.1 技术选型  
| 模块 | 技术/工具 | 说明 |
| --- | --- | --- |
| 终端（Android） | Java / Android SDK / Gradle | 主界面 `MainActivity`、前台服务 `LocationService`、GNSS 监听 `GNSSStatusListener` 等 |
| 服务器 | Java + MySQL + JDBC | `CloudDataReceiver.java` 负责 TCP 接收并写入数据库 |
| 数据协议 | 自定义二进制结构（小端） | 与 `gnss_data.h` 布局一致，字段包含时间、经纬度、速度、卫星信息等 |
| 网络 | TCP（最终版本仅保留 TCP） | APP 与服务器之间的可靠传输通道 |

### 2.2 系统架构（文字流程）  
1. **手机端**：  
   - `LocationManager` 获取 GNSS 位置 → `GNSSStatusListener` 获取卫星状态；  
   - `GNSSData` 整理 DOP、C/N0 等 → `BinaryDataPacket` 打包字节流；  
   - `UploadLocationTask` 通过 TCP 将数据发送至服务器。  
2. **网络层**：  
   - 通过 TCP Socket 连接（可配置本地/远程 IP 与端口）；  
   - 客户端按固定间隔（默认 5 s）发送数据包。  
3. **服务器端**：  
   - `CloudDataReceiver` 监听端口 → 接收字节流 → 解析 → JDBC 写入 MySQL；  
   - 数据库 `gnss_data` 存储结构化定位记录，供后续分析可视化。

### 2.3 核心实现  
- **GNSS 数据获取**：只启用 `GPS_PROVIDER`，并要求高度/速度/方向。`onLocationChanged()` 实时更新 UI，并缓存最新 `Location` 供上传。  
- **卫星状态监听**：`GNSSStatusListener` 统计可见卫星数、参与定位数量、信号强度 (C/N0)，并生成建议。  
- **二进制打包**：`BinaryDataPacket` 使用 `ByteBuffer` 小端写入，经纬度、高度、速度、方向、卫星列表（最多 40 颗）、PDOP 等。  
- **TCP 上传**：`UploadLocationTask` 读取配置(IP/Port)、建立 Socket、发送数据、处理异常；支持前台服务持续上传。  
- **云端接收**：`CloudDataReceiver` 解析自定义协议，并调用 MySQL JDBC 写入 `gnss_data` 表；`初始化数据库.sql` 用于建库建表。

## 第 3 章 能够获取的 GNSS 信息

### 3.1 基本定位信息  
| 信息项 | 描述 |
| --- | --- |
| 纬度/经度 | WGS-84 坐标系，双精度表示，精度可达 10⁻⁶ 度（约 0.1 m 级显示）。 |
| 高度 | 单位米，相对椭球/海平面；无数据时置 0 并注明。 |
| 对地速度 | 单位 m/s（可换算 km/h），若无速度信息则显示 “0.00 m/s (静止)”。 |
| 航向/方位 | 单位度，0–359.9；若无航向信息则显示 “0.0° (静止)”。 |

### 3.2 时间信息  
| 信息项 | 描述 |
| --- | --- |
| UTC 时间戳 | 来自 GNSS 卫星，精度高，用于排序与多端同步。 |
| 日期 | 由 UTC 时间派生，便于分表和统计。 |

### 3.3 卫星状态信息  
| 信息项 | 描述 |
| --- | --- |
| 可见卫星数 | 当前可见的所有卫星数量。 |
| 参与定位卫星数 | 用于解算位置的卫星数量。 |
| 卫星编号与星座 | `gnssId` 区分 GPS/北斗/GLONASS 等，记录 SVID/PRN。 |
| 仰角/方位角 | 用于分析卫星空间分布（0–90° / 0–360°）。 |
| 信噪比 (C/N0) | 单位 dB-Hz，表示信号强度；UI 统计平均值及强/中/弱分布。 |

### 3.4 定位质量信息  
| 信息项 | 描述 |
| --- | --- |
| 定位模式/状态 | 是否已获得定位解算（2D/3D Fix）。 |
| 精度因子 DOP | PDOP（位置）、HDOP（水平）、VDOP（垂直）；PDOP 已在 APP 中显示。 |
| 定位精度 (Accuracy) | Android `Location.getAccuracy()`，以米计并显示等级提示。 |
| 数据有效性 | 通过是否有 Fix、卫星数量、时间戳是否新鲜等综合判断。 |

## 第 4 章 使用说明

### 4.1 硬件条件  
- Android 智能手机（支持 GNSS，建议在室外/靠窗使用）；  
- 一台云服务器（具公网 IP，开放 TCP 端口，安装 Java + MySQL）。

### 4.2 手机端部署  
1. 从 `releases` 目录拷贝最新 APK（如 `LocationUploader-v1.0.32-GPS-Only.apk`）到手机；  
2. 安装并授予位置、网络权限；  
3. 首次启动后按提示配置网络参数。

### 4.3 服务器端部署  
1. 上传 `CloudDataReceiver.java`、JDBC 驱动、`初始化数据库.sql` 等文件；  
2. 执行 SQL 创建 `gnss_data` 数据库与数据表；  
3. 修改 `CloudDataReceiver` 中的数据库 URL、账号与端口；  
4. 运行启动脚本，监听指定 TCP 端口，确保防火墙/安全组放通。

### 4.4 APP 操作步骤  
1. **配置网络**：  
   - “本地网络配置”用于局域网调试；  
   - “远程网络配置”填入云服务器 IP/端口（传输方式固定为 TCP），可测试连通性。  
2. **获取位置**：  
   - 点击“获取位置”，APP 通过 GPS 获取实时位置与卫星状态。  
   - 若 GPS 未开启，会提示前往系统设置。  
3. **开始上传**：  
   - 点击“开始上传”进入连续采集，按默认 5 s 上传一次；  
   - 上传期间可观察 UI 中的最新数据与卫星信息。  
4. **停止上传**：  
   - 点击“停止上传”即可终止前台服务与 TCP 连接。  
5. **数据查看**：  
   - 登录服务器 MySQL，查询 `gnss_data` 表；  
   - 可导出 CSV 或使用其他工具进行可视化分析。

## 第 5 章 代码说明

### 5.1 主要代码模块  
| 文件 | 功能概要 |
| --- | --- |
| `MainActivity.java` | UI 交互、位置获取、上传控制、本地/远程配置对话框。 |
| `LocationService.java` | 前台服务，保证后台持续上传。 |
| `GNSSStatusListener.java` | 监听 GNSS 状态，统计卫星数量、C/N0、DOP 等。 |
| `GNSSData.java` | 封装卫星列表、PDOP、平均 C/N0 等。 |
| `BinaryDataPacket.java` | 将 `Location + GNSSData` 打包为二进制协议（小端）。 |
| `UploadLocationTask.java` / `PersistentUploadTask.java` | TCP 上传逻辑。 |
| `CloudDataReceiver.java`（服务器端） | TCP 接收、解析二进制数据并写入 MySQL。 |
| `初始化数据库.sql` | 建库建表脚本，定义 `gnss_data` 表结构。 |

### 5.2 核心代码片段说明  
- **GPS 请求**：在 `MainActivity` 中只启用 `LocationManager.GPS_PROVIDER`，并要求高度/速度/方向。  
- **卫星数据**：`GNSSStatusListener` 通过 `GnssStatus` 回调统计卫星信息，写入 `GNSSData`。  
- **二进制打包**：`BinaryDataPacket` 使用 `ByteBuffer.order(LITTLE_ENDIAN)` 写入各字段，限制卫星数量为 40。  
- **TCP 上传**：`UploadLocationTask` 从 SharedPreferences 读取 IP/Port，建立 Socket，发送数据包，并处理异常与重试。  
- **服务器接收**：`CloudDataReceiver` 按结构体长度读取数据，转换为 Java 对象后写入 MySQL。

### 5.3 关键参数配置  
| 参数 | 位置 | 说明 |
| --- | --- | --- |
| 服务器 IP / 端口 | APP 设置界面（SharedPreferences） | 分别对应本地/远程配置，远程传输方式固定为 TCP。 |
| 上传间隔 `UPLOAD_INTERVAL` | `MainActivity` | 默认 5000 ms，可按需要调整。 |
| 位置精度阈值 `ACCURACY_THRESHOLD` | `MainActivity` | 默认 100 m，用于判断是否停止请求更高精度。 |
| 最大卫星数 `MAX_SATELLITES` | `BinaryDataPacket`, `GNSSData` | 默认 40，防止缓冲区溢出。 |
| MySQL 连接参数 | `CloudDataReceiver.java` | 包括主机、端口、数据库、用户、密码、是否允许公钥检索等。 |
